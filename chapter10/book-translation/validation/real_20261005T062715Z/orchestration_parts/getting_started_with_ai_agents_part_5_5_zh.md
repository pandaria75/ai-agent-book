**上下文层**安全护栏管控**模型能看到什么内容**，在内容进入上下文之前进行拦截。它们通常包含四种机制。**相关性分类器**[待审]标记偏离主题的查询——比如向一个编程助手询问"帝国大厦有多高？"**安全分类器**[待审]检测越狱攻击[待审]（诱导模型绕过其安全限制）和提示注入（在输入中嵌入恶意指令）；关键区别在于，越狱是用户试图绕过模型自身的限制，而提示注入是攻击者通过网页或文档等外部数据间接操纵模型。**内容审核**[待审]标记有害或不当的输入，例如暴力或歧视性内容。**基于规则的防护**[待审]针对已知威胁（如 SQL 注入）应用确定性措施——黑名单、输入长度限制、正则表达式过滤器。来源标注以及"指令"与"数据"的分离也属于这一层；第2章将对此展开讨论。

Anthropic 的"宪法分类器"（Constitutional Classifiers）[待审]提供了基于分类器的安全护栏在实践中的一个范例[^ch1-3]。其设计包含三个关键要素。第一，**规则驱动训练**[待审]：使用指定允许和禁止内容的自然语言规则，为输入和输出分类器生成合成训练数据。第二，**联合上下文判断**[待审]：新一代分类器将用户的问题和模型的回答放在一起检查，因为有些回答单独看完全正常（例如"如何使用食品调味料"），但结合问题才能看出"食品调味料"其实是化学试剂的暗语。第三，**两阶段筛查**[待审]：一个极其轻量的探针[待审]——几乎零成本地读取模型的内部激活——首先检查每段对话，任何可疑内容都会升级到更强大的分类器进行审查，而非直接拒绝。这样第一阶段可以容忍更多的误报而不损害用户体验，同时大幅降低整体成本。

[^ch1-3]: Anthropic. "下一代宪法分类器：更高效地防御通用越狱攻击", 2026. https://www.anthropic.com/research/next-generation-constitutional-classifiers; 论文：Cunningham et al., "Constitutional Classifiers++: Efficient Production-Grade Defenses against Universal Jailbreaks", arXiv:2601.04603

但这一层存在结构性上限：**智能体无法可靠地判断提示注入是否已经污染了自己的上下文**。因此，上下文层可以降低攻击的成功率，但无法提供保证——这正是其下两层存在的必要性。

**执行层**安全护栏管控**模型能做什么**，在动作生效之前进行校验。其核心是**工具风险评级**[待审]：每个工具根据可逆性、权限级别和财务影响被标记为低、中、高风险，高风险操作需要额外审查或人工确认。关键在于，这项审查必须由**上下文之外**的机制执行——独立的审查流程、最小权限凭证、沙箱隔离、人在回路——否则同一次攻击可能同时破坏智能体及其防护措施。返回给用户的回复本身就是一个动作（第4章将其归类为用户通信工具），因此**输出检查**也属于这一层：**个人可识别信息（PII）过滤器**[待审]对输出进行筛查，过滤身份证号、电话号码等个人可识别信息以防止不必要的暴露；**输出校验**[待审]检查内容，确保回复符合品牌价值。

**数据层**安全护栏管控**系统被允许对数据做出哪些变更**。它们通过稳定且经人工审核的机制来强制执行谁可以对哪些记录执行哪些操作：数据库中的行级安全策略、约束和校验器、受控视图和存储过程，以及由可信运行时绑定的、不可伪造的访问上下文。这一层的价值恰恰在于它不依赖于上面两层的正确性——即使提示注入成功、生成的代码完全省略了权限检查，未授权操作仍然会在数据层被拒绝。第5章通过动态生成软件的例子展开这一层的内容。

#### 人工干预

**人在回路**[待审]干预是一项关键的保护措施：它让智能体在提升真实世界性能的同时不损害用户体验。它在早期部署阶段尤为重要，有助于识别失败模式、暴露边界情况，并建立稳健的评估循环。

有了人在回路机制，无法完成任务的智能体可以优雅地移交控制权。在客服场景中，这意味着升级转接人工坐席；对于编码智能体，这意味着将控制权交还给开发者。

通常有两类主要情况会触发人工干预：

**超出失败阈值**
为智能体的重试次数和操作次数设定上限。一旦智能体超过这些上限，就升级转交人工。

**高风险操作**
敏感的、不可逆的或高风险的操作应触发人工监督——至少在团队对智能体的可靠性建立足够信心之前。典型例子包括授权大额退款或处理付款。

回到驾驭层五要素的主线——来看看它们与本书结构的关系。

### 驾驭层五要素与"构建"部分

**两个公式在不同细节层次上描述了同一架构。****智能体 = 大语言模型 + 上下文 + 工具**为全书提供了组织框架：第2至6章涵盖构建，第7至9章涵盖评估与改进，第10章涵盖协作。**智能体 = 模型 + 驾驭层**将上下文和工具展开为生产系统的五项职责：上下文管理、工具接口、约束、验证与纠正。因此，它**解释的是构建章节所涵盖的架构**，而非为全部十章提供独立的大纲。

在这一范围内，驾驭层五要素与第2至5章的对应关系如下：

| 驾驭层关注点 | 对应章节 | 核心内容 | 安全问题 |
|---|---|---|---|
| 上下文管理 | 第2章（上下文工程） | 提示工程、智能体状态栏、上下文压缩、智能体技能 | 提示注入与上下文污染 |
| 跨会话上下文管理 | 第3章（用户记忆与知识库） | 用户记忆、RAG、结构化索引、智能体化 RAG | 敏感信息暴露、隐私保护 |
| 工具接口与约束 | 第4章（工具） | 工具分类、权限控制、MCP 标准、主动工具发现 | 误操作、未授权访问、不可逆操作 |
| 验证与纠正 | 第5章（编码智能体与通用智能体） | 编码智能体的驾驭层、测试驱动开发、编码化规则 | 身份冒充、责任归属 |

第6章（交互）不属于五要素中的任何一个；它展开的是观测空间和行动空间本身的形式与时机。第7至9章探讨**我们如何知道驾驭层构建得正确，以及如何持续改进它**。第10章将单一智能体的驾驭层替换为多个智能体之间的协作结构。强行将这些章节归入五类只会削弱这些类别的实用性。

安全同样不是按章节划分的：它是一个贯穿全书的横切关注点（影响系统多个部分的问题），由上一节所述的三层安全护栏组织——上下文层、执行层、数据层。上表中的"安全问题"列指出了各章所涉及的主要安全问题。

Anthropic 在构建长时间运行智能体方面的实践表明，驾驭层设计能够解决模型自身无法解决的问题。他们将复杂任务拆分给"初始化智能体"（设置环境、分解任务列表）和"执行智能体"（每次会话推进增量进度并留下清晰的交接工件），使用结构化的驾驭层来应对长任务的两种失败模式：上下文耗尽和过早宣布任务完成。后续章节将逐个组件地剖析驾驭层——第2章从最核心的上下文工程开始，第5章则展示编码智能体中驾驭层工程的完整实践。

## 贯穿全书的设计模式

后续章节反复使用同一组设计模式，因此在此集中给出规范的命名和定义。

**提案者-评审者**[待审]：创建者和评审者在不同的上下文中工作。评审者评估的是工件本身——渲染结果、测试输出或结构化的调用参数——而非创建者的推理过程。其前提是**自我评审不可靠**：模型可能难以识别自身的盲区，也无法察觉上下文是否已被提示注入污染。第3章用它来更新知识；第4章用它对工具调用进行事前审批和事后验证（Sidecar 是其只读变体）；第5章的 PPT、视频和日志实验都基于它构建；第7章用它评估用户界面；第9章用它审查更新提案；第10章讨论它在对等协作中的形态，以及为什么智能体不能自我评审。

**渐进式披露**[待审]：不将所有内容一次性放入上下文，而是先提供一个可搜索的目录，按需加载详细信息。它同时优化两件事——上下文预算和选择准确率。第2章的智能体技能是其原型（元数据常驻，正文按需加载）；第3章的分层检索、第4章的主动工具发现与分页截断、第10章的智能体发现都是其变体。

**仅追加**[待审]：状态通过追加来演进，已写入的内容绝不原地修改。这带来的是可缓存性、可回放性和可审计性。第2章展示了保持 KV缓存前缀稳定的性能收益：前缀中越早的改动会使越多缓存失效。第3章的事件式记忆和第4章将新发现的工具模式追加到轨迹而非插入前缀的做法，都遵循同一原则。

**边界集 + 保留集**[待审]：每次变更都必须在"它应该改变的样本"和"它不应影响的样本"上同时验证。只测试前者会将过拟合误判为进展；只测试后者会将无效的变更误判为安全的变更。第7章的回归任务、第8章的训练/评估隔离以及第9章的更新提案验证都建立在这对集合之上。

**最小差异、可逆**[待审]：保持每次变更尽可能小，携带其来源信息，并且可以独立回滚而非整体重写。这使得归因成为可能——当出现问题时，可以追溯到某一个具体的变更。第3章的知识更新、第5章的代码补丁和第9章的提示词与程序更新都遵循这一原则；本章开头给出的三条更新路径（上下文自适应、外部工件更新、参数更新）本身就是按可逆性从高到低排列的。

## 章节小结

本章构建了一个以实践为导向的理解和构建智能体的框架。

**智能体 = 推理引擎 + 工作上下文 + 行动接口**：大语言模型提供推理与决策，上下文提供决策时可用的信息工作集，工具提供行动接口。三者缺一不可。

**扩展上下文与工具是主要的能力杠杆**：一旦模型确定，重新定义或扩大观测空间和行动空间——即扩展上下文与工具——往往能直接将不可解的任务变为可解的任务。Manus 和 OpenClaw 的演进表明，智能体的多功能性很大程度上来自可用接口的扩展；这种扩展必须保持按需加载，并与权限和验证相配合。

**上下文是决定性因素**：上下文由静态前缀（系统提示词 + 工具定义）和动态轨迹（消息历史）组成。消融实验表明各组件并不等价：移除工具定义或工具结果会直接剥夺行动能力或闭环能力，而移除其余两者的代价则取决于这些信息能否从当前观测中重建。推理-行动循环的本质是不断向轨迹中追加，使模型持续推进任务。

**驾驭层是竞争优势**：模型能力正在趋于同质化；真正的差异化因素是驾驭层——围绕上下文和工具构建的约束、验证与纠正机制，它们使可靠的任务完成成为可能。在生产级智能体系统中，绝大部分驾驭层代码用于这些安全防护，而不仅仅是上下文和工具本身。

**从工作流到自主智能体**：先是提示词，然后是工作流，最后是自主智能体——这种顺序是减少意外行为的最实用方式。每种编排模式都有其适用的场景；没有一种模式在所有场景下都是最优的。

**五种设计模式贯穿全书**：提案者-评审者、渐进式披露、仅追加、边界集 + 保留集、最小差异 + 可逆。

**安全是架构问题**：安全必须从第一行代码开始考虑，而非在上线前打补丁。安全护栏按绕过难度分为上下文层、执行层和数据层；后续所有安全讨论都沿用这一结构。

下一章将深入探讨驾驭层最核心的组件：上下文工程。第8章涵盖智能体概念在强化学习中的学术根源，并比较传统强化学习与现代大语言模型智能体。
