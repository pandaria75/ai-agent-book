1. **工具结果预算控制**：大体积工具输出存放在磁盘上；模型只看到预览摘要。替换决策一经做出即冻结，以确保缓存一致性。
2. **直接删除噪声**：低价值内容（例如在大量搜索结果中只被引用了几行的内容）直接删除而不做总结——对噪声做总结只是浪费 token。
3. **API 级微压缩**：利用 API 的上下文编辑能力，指示服务器从前缀中移除特定工具结果，而本地消息列表保持不变。这一层的优势是零本地实现成本——服务器一次完成。但根据本章的前缀不变性原则，移除点之后的缓存也会失效，需要重建。因此，它适合在上下文即将溢出、反正必须付出缓存重建成本时使用，而非频繁触发。
4. **归档式总结**：逐轮执行结构化总结（类似 `git log`，每轮保留独立记录，而非 `git squash` 将其合并为一条），保留对话的逻辑脉络。
5. **完全压缩**：由 LLM 驱动的完整压缩，作为最后手段。即便如此也分两步执行：先尝试压缩会话记忆；失败后再执行完全压缩。完全压缩还配备了针对连续失败的熔断器（在连续失败达到一定次数后自动停止重试的机制）——生产数据显示，许多会话陷入反复压缩失败的循环，熔断器防止在这些会话上做不必要的开销。

### 压缩策略的设计原则

我们已经分析了压缩的三个动机——控制长度、提升推理质量、缓解上下文焦虑——以及"上下文学习本质上是检索"的内部机制。在此基础上，可以提炼出四条原则来指导具体压缩策略的设计。此处讨论的压缩服务于当前任务；当必须将多个任务的轨迹离线整合为持久经验时，问题就变成了第 9 章讨论的持续演进问题。

- **信息价值的非均匀分布**：关键决策点（如人员名单）比支撑证据（如新闻详情）更有价值；支撑证据又比冗余噪声（如导航栏和页脚广告）更有价值。
- **语义完整性**："Sutskever left OpenAI in May 2024" 不能压缩为 "Sutskever left"——时间和公司名是关键的、不可妥协的信息。
- **任务相关性**：同一内容对不同任务应产生不同的压缩结果，如"查找创始人名单"与"了解个人背景"。更一般地说，检索任务需要广度，分析任务需要深度，创意任务需要启发灵感的素材。理想情况下，智能体应根据任务自适应地调整压缩策略。
- **压缩即理解**：有效的压缩需要深层语义理解，因此执行压缩的模型应在能力上接近主模型。这构成了一种递归架构，一个模型调用另一个模型。由此产生的摘要可以被审查并跨会话复用。

虽然压缩增加了计算开销——每次压缩都需要额外的 LLM 调用——但相对于由此带来的 token 成本节省和任务成功率提升，其投资回报率可能极高。实验表明，上下文感知压缩可将 token 使用量减少超过 75%。

压缩最容易丢失的是早期架构决策、约束背后的理由以及失败的路径。因此，**智能体应频繁将进展保存到文档中**，而非让所有信息散落在执行历史中。正如重要的公司信息应存放在文档而非聊天记录中，智能体也需要编写和更新文档的习惯。如果你的模型缺乏这一习惯，就通过提示词和 Skills 加以强化。

### 隔离优于压缩：子智能体上下文隔离

压缩是在信息已进入上下文**之后**将其移除。更直接的方法是从一开始就让大体积的中间信息不进入主上下文。这就是**子智能体上下文隔离**：主智能体会将产生大量中间内容的任务（如"在代码库中做一次广泛搜索"）委派给独立的子智能体。子智能体在自己的上下文中完成探索，只向主智能体返回几百 token 的简明摘要。

就同一任务"找到代码库中处理支付回调的函数"比较两种方式。如果主智能体自行搜索，它可能将数十个文件和数万 token 的原始代码带入主上下文。找到目标后，大部分材料仍作为永久噪声留在窗口中，后续必须通过压缩移除。而如果委派给搜索子智能体，主上下文只增加两条消息：一条任务描述和一条结论（"函数是 `src/payment/callbacks.py` 中的 `handle_callback`，另有两处调用点"），而中间过程的数万 token 随子智能体的上下文一同丢弃。

这本质上是**用隔离替代压缩**：压缩是有损的、事后的补救措施，需要额外的 LLM 调用；而隔离从一开始就将噪声挡在主上下文之外，且不影响主智能体的 KV Cache 前缀。代价是子智能体看不到主智能体的完整上下文，因此任务描述必须自包含，目标必须清晰。这又回到本章的核心主题：上下文决定能力上限，对子智能体同样成立。Claude Code 的 Task 工具和 Deep Research 系统中使用的检索子智能体就是这一模式的生产实现。第 4 章讨论子智能体作为协作工具的完整设计，第 10 章涵盖多智能体系统的上下文架构。

## 本章小结

上下文工程的主线是显式的信息管理：API 消息结构定义骨架；稳定的前缀提升 KV Cache 命中率；提示词、Skills 和状态栏分别承载规则、按需知识和当前状态；压缩在保留决策、约束、失败和来源的同时提升历史信息的密度。

本章讨论的是**单个任务内**的状态更新和上下文退化。下一章将超越单个上下文窗口内的信息管理，进入跨任务的持久知识系统：用户记忆和知识库。这些系统让智能体能够随时间积累经验，逐渐成为一个更理解用户的助手，或一个拥有更专业领域知识的专家。
